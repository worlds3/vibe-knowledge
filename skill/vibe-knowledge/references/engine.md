# 引擎与实现

## 核心原则

- **`render(t)` 必须是纯函数**：同一个 t 永远画出同一帧。随机数一律用 `hash(n)`，禁止 `Math.random()`；禁止"每帧累加"的物理状态（粒子位置 = f(t, 序号)）。这样播放可随意跳转，导出可逐帧离线渲染。
- 逻辑坐标恒为 **1920×1080**。导出时 `setScale(2)` 把画布变成 3840×2160，`render` 开头 `ctx.setTransform(SS,0,0,SS,0,0)`。`shadowBlur` 不受变换影响，要手动乘 `SS`（`glowText` 已处理）。
- 播放时 `t = audio.currentTime`，天然音画同步；导出时音频由 `AudioEncoder` 同步写入。

## 模板结构（assets/template.html）

| 区块 | 改什么 |
|---|---|
| `CONFIG` | 片名、英文片名、总长 `dur`（= BGM 的 `musicEnd`）、`ending: 'choice' | 'title'` |
| `TINTS` | 每段背景色调 `[开始秒, 主色, 副色]` |
| `CAPS` | 字幕 `[开始, 结束, '文字 {金色} [玫红]\n第二行']` |
| `LABELS` | 左上角章节标签 `[开始, 结束, '01', '章节名']` |
| `sceneXxx(t)` | 每个场景一个函数，用绝对时间写动画 |
| `render(t)` | 按时间段分派场景；转场重叠区可以同时调用两个场景 |
| `endingChoice` / `endingTitle` | 结尾组件，传参即可 |

调试：`?t=50` 从 50 秒开始、`?hide` 隐藏面板、`?ending=title` 切结尾、`?fps=30&scale=1` 快速导出；控制台 `sheet([...])` / `dump(name, [...])` 看帧。

## 工具函数

- `seg(t, a, b)`：t 在 [a,b] 内的 0→1 进度；`win(t, a, b, fi, fo)`：带淡入淡出的可见度
- `E.out3 / io3 / outBack / inExpo`：缓动。入场用 `outBack`（带回弹），镜头推进用 `in3`，移动用 `io3`
- `glowText`、`spacedText`（英文宽字距）、`rr`（圆角矩形）、`heartPath`
- `ring`（冲击波圆环）、`burst`（粒子爆炸）、`flash`（全屏闪白 / 闪色 / 渐黑）
- `env(t)`：BGM 平滑能量 0–1；`kick(t)`：鼓点脉冲 0–1。用来调光晕大小、发光强度、缩放，画面就会"跟着音乐呼吸"

## 转场配方（丝滑的关键）

所有转场都遵循：**推进到细节 → 细节铺满 → 下一场从同色/同形展开**，交叠 ≤ 0.5 秒。

1. **推镜铺满**：`zoomTo(fx, fy, Math.pow(60, E.in3(p)), E.io3(p))`，焦点是一个实心圆形元素（徽章、按钮、发光点）。放大倍数要让它的半径 > 画面半对角线（1920×1080 约 1100px）。下一场开头画一层同色全屏渐变，0.4 秒内淡出，同时新元素从中升起。
2. **爆点闪白**：推进到一个爆炸 / 高光点，最后 0.5 秒 `flash` 到 0.95；下一场开头从白光里凝出一个大数字或标题。
3. **形变接力**：上一场的 N 个元素（格子、点、柱子）用同一份数据 `lerp` 到下一场的位置。例如模拟网格 → 散点 → 曲线，曲线上的点 → 两团粒子 → 一条时间轴。两个场景函数在交接区共用同一组坐标，避免重复绘制（见下方 bug 2）。
4. **鼓点落位**：在 BGM 爆发点让粒子瞬间吸附成下一场的结构 + 冲击波圆环 + 轻闪。

## 场景写法套路

- **物件型开场**：手机 / 卡片 / 骰子先 `outBack` 入场 + 两圈冲击波 + 扫光；周围放一圈环绕元素（数量和主题数字一致，比如 10 个人），1–2 秒后吸进物件
- **柱子 / 候选人**：用事件表 `PEV[i] = [{t, h:'true'|'hid', c, g}]` 描述每根柱子的状态变化，`pillarState(i,t)` 依次插值；配一个走动的「你」指示器
- **可视化证明**：先用网格翻牌演示"大量模拟"（计数器从 0 滚到 10 万，成功率实时收敛），再让格子飞成散点，噪声振幅随时间收缩，收敛到理论曲线，最后标峰值
- **安静段**：粒子分成两团（例如 37% 金 / 63% 灰），慢速漂移 + 光晕，文案讲反转或另一面
- **生活应用**：一条时间轴，每个应用换一次刻度和标签，标记点保持在同一比例附近，视觉上连续

## 踩过的坑

1. **file:// 打不开音频**：浏览器禁止 `fetch` / 解码本地文件。模板已兜底（改为手动选择 bgm），但首选双击 `start.bat`。
2. **交接区重复绘制**：两个场景在交叠时间都画同一批点，颜色叠加变白。交接时让前一个场景在 t > 交接点后停画这批点。
3. **散点被 clamp 成直线**：给数据点加噪声后用 `clamp` 会在坐标轴边缘堆成一条线。改为镜像反射：`y = abs(y); if (y > max) y = 2*max - y`。
4. **缩放后字太小**：场景如果整体缩放，所有标签字号要重新检查，屏幕上的最终字号 ≥ 30px（4K 下 ≥ 60px）。
5. **字体加载慢**：Google Fonts 在国内可能被墙，模板最多等 6 秒后用系统字体（微软雅黑）兜底。必要时提醒用户。
6. **浏览器面板截图超时**：用 `frame_sink.py` + `dump()` 存图再用 Read 看，更稳定也更清晰。
7. **AAC 码率**：`AudioEncoder` 的 AAC 在 256k 下不被支持会退成 Opus，保持 192k。
8. **4K 编码**：H.264 需要 level 5.2（`avc1.640034`）才能 4K60；模板会依次退到 HEVC / AV1 / VP9。导出速度约 6 倍实时（130 秒 ≈ 13–15 分钟），导出时标签页必须在前台。
10. **大量小方块很慢**：逐格 `fillStyle` + `fillRect` 画 5000+ 像素格，4K 下单帧会到 100ms 以上，实时预览会卡。改成把颜色写进一张小 `ImageData`（如 96×54），`putImageData` 后关掉 `imageSmoothingEnabled` 整体 `drawImage` 放大，需要格缝再叠一张预渲染的格线图。逐帧用 `performance.now()` 量最重的几个时间点，4K 下控制在 40ms 以内。
9. **开头空镜**：第 0 帧不能是空的或纯黑，物件要在 0.3 秒内可见，否则信息流里会被划走。

## 检查清单

- [ ] 第 0.5 秒已有视觉锚点，第一句字幕和观众相关
- [ ] 段落边界对上 BGM 突变点（±0.3 秒）
- [ ] 每个转场前后各看一帧：铺满后颜色 / 形状和下一场开头一致，没有黑帧、没有硬切
- [ ] 字幕不和画面元素重叠；所有小字在 1080p 下清晰可读
- [ ] 没有顶部进度条 / 常驻页眉；结尾是二选一或片名 + 英文，没有「评论区见」
- [ ] 二选一结尾：切换周期能整除结尾时长，最后几秒可以无缝循环
- [ ] 控制台无报错；短导出测试通过（3840×2160、AAC）
